# Support

## Learning Rust with Rustly

- The platform itself: [rustly.tech](https://rustly.tech)
- Learn paths, Trials, and cheatsheets are the primary support surface.
- Community Q&A lives at [rustly.tech/questions](https://rustly.tech/questions).

## Something is broken

| Situation | Where to go |
| --- | --- |
| Bug in a Rustly repository | Open a bug issue on that repository |
| Wrong or unclear lesson / Trial content | Open a content issue on [`content`](https://github.com/rustly-tech/content/issues) |
| Incorrect judge verdict | Open a bug issue on [`judge`](https://github.com/rustly-tech/judge/issues) with the submission id |
| Security vulnerability | **Do not open an issue.** See [SECURITY.md](SECURITY.md) |
| Account, billing, or moderation | contact@rustly.tech |
| Code of Conduct concern | conduct@rustly.tech |

## Before opening an issue

1. Search existing issues, including closed ones.
2. Include the repository commit SHA or release version.
3. For judge issues, include the submission id and the verdict you received.
   Do **not** paste hidden test content, even if you believe you have seen it -
   report that as a security issue instead.

## Response expectations

Rustly is an early-stage open source project. Issues are triaged on a best-effort
basis. Security reports are prioritised above everything else.
